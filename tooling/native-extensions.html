Writing Native Extensions ​

A native extension is a shared library that registers new functions into the VM. Kolt loads it and calls those functions like any other throwing call.

kolt
import std "ffi"
import std "io"

try ffi.load("./libmyext.so")
const r = try ffi.call("my_add", ffi.KoltFFIInt, 3, 4)
io.println(r) // 7

ffi.load needs the file path. ffi.call needs the registered name, a return tag, and the args. It throws when the library or the name is missing.

Minimal C++ Extension ​

cpp
#include "kolt.hpp"

// runs when Kolt loads the library, registers every function
extern "C" EXPORT_API void kolt_extension_init(KoltCtx ctx)
{
    ctx.register_native("my_add", my_add);
}

KoltValue my_add(KoltCtx raw_ctx, const KoltValue *args, int argc)
{
    kolt::Context ctx(raw_ctx);

    if (argc != 2 || !ctx.is_int(args[0]) || !ctx.is_int(args[1])) {
        return ctx.make_error("Expected 2 int args.").release();
    }

    // read the two args as ints
    auto a = ctx.get_int(args[0]);
    auto b = ctx.get_int(args[1]);

    // build the result, hand ownership to the VM
    return ctx.make_int(a + b).release();
}

Copy extensions/kolt.h and extensions/kolt.hpp next to the extension source. kolt.hpp wraps the raw table with RAII values so temps free themselves.

Entry Point ​

cpp
// exact name, exact signature, C linkage, exported
extern "C" EXPORT_API void kolt_extension_init(KoltCtx ctx)
{
    ctx.register_native("my_add", my_add);
    ctx.register_native("my_greet", my_greet);
}

The loader looks for kolt_extension_init and fails the ffi.load when it is missing. Register one name per function.

Reading Args ​

cpp
// ints and floats, 0 when the arg is the wrong type
auto n = ctx.get_int(args[0]);
auto x = ctx.get_float(args[1]);

Check the count first, Kolt leaves that check to the extension.

cpp
// guard the arg count up front
if (argc < 2)
{
    return ctx.make_error("my_add needs 2 args").release();
}
cpp
// strings come back as a C string, use it right away
const char *name = ctx.get_string(args[0]);
std::string copy(name); // copy it for storage past the call

The string pointer lives in a shared scratch slot. The next get_string call overwrites it.

cpp
// buffers come back as bytes plus a length
size_t len = 0;
const unsigned char *bytes = ctx.raw()->get_buffer(ctx.raw(), args[0], &len);
cpp
// probe the type before reading
if (!ctx.is_number(args[0]))
{
    return ctx.make_error("expected a number").release();
}

Probes: is_number, is_int, is_float, is_string, is_buffer, is_function, is_array, is_tuple, is_map, is_pointer. Each answers about one value.

Returning Values ​

cpp
return ctx.make_int(42).release();

Ints.

cpp
return ctx.make_float(4.5).release();

Floats.

cpp
return ctx.make_string("hi").release();

Strings. Pass a null terminated C string.

cpp
return ctx.make_bool(true).release();

Bools.

cpp
return ctx.make_null().release();

Null.

cpp
return ctx.make_error("boom").release();

Errors. Kolt sees a throwing call, so the Kolt side uses try.

cpp
const char *data = "...";
return ctx.make_buffer(data, len).release();

Buffers. The bytes are copied in, the caller pointer can go away after.

Ownership ​

cpp
// temps built but not returned must be freed
KoltValue arr = ctx.make_array().raw();
KoltValue tmp = ctx.make_int(1).raw();
ctx.raw()->array_push(ctx.raw(), arr, tmp);
ctx.raw()->free_value(ctx.raw(), tmp);
return arr; // the returned value belongs to the VM, do not free it

Two rules. Free every held temp. Never free the returned value or the incoming args. The C++ wrapper does the temp part through destructors, and .release() marks the return value as VM owned.

Arrays ​

cpp
// build an array to return
kolt::Context ctx(raw_ctx);
auto arr = ctx.make_array();
arr.push(int64_t(1));
arr.push("two");
arr.push(3.5);
return arr.release();
cpp
// read one that came in
int len = ctx.raw()->array_length(ctx.raw(), args[0]);
KoltValue first = ctx.raw()->array_get(ctx.raw(), args[0], 0);
// first is borrowed, clone it before freeing or returning it
kolt::Value kept = ctx.clone_value(first);
ctx.raw()->free_value(ctx.raw(), first);
return kept.release();

Out of range reads give null instead of crashing.

Maps ​

cpp
// build a map to return
auto m = ctx.make_map();
m.set("ok", true);
m.set("count", int64_t(3));
return m.release();
cpp
// read one key
KoltValue v = ctx.raw()->map_get(ctx.raw(), args[0], "name");

Missing keys come back null.

Tuples ​

cpp
// read tuple elements, same shape as arrays
int len = ctx.raw()->tuple_length(ctx.raw(), args[0]);
KoltValue first = ctx.raw()->tuple_get(ctx.raw(), args[0], 0);
cpp
// build a tuple to return, elements are copied in
KoltValue elems[2] = {args[0], args[1]};
return ctx.make_tuple(elems, 2).release();

Calling Back Into Kolt ​

cpp
// only call values that are actually functions
if (!ctx.is_function(args[0]))
{
    return ctx.make_error("expected a function").release();
}
KoltValue no_args = nullptr;
return ctx.call_function(args[0], &no_args, 0).release();
cpp
// inspect a function value first when its shape matters
KoltFunctionInfo info = ctx.get_function_info(args[0]);
// info.is_function, info.name, info.argument_count, info.variadic, info.native

Keeping Values Across Calls ​

cpp
// clone to hold a value past this call, free when done with it
kolt::Value saved = ctx.clone_value(args[0]);
// ... later ...
// saved frees itself when it drops, or release it to pass on

Borrowed args and array or map reads die with the call. Stashed values need a clone first.

Native Structs And Handles ​

cpp
// hand a native struct to Kolt as an opaque pointer
struct Counter
{
    int64_t n;
};

KoltValue counter_new(KoltCtx raw_ctx, const KoltValue *, int)
{
    kolt::Context ctx(raw_ctx);
    auto *c = new Counter{0};
    return ctx.wrap_pointer(c).release();
}

KoltValue counter_bump(KoltCtx raw_ctx, const KoltValue *args, int)
{
    kolt::Context ctx(raw_ctx);
    auto *c = static_cast<Counter *>(ctx.unwrap_pointer(args[0]));
    c->n += 1;
    return ctx.make_int(c->n).release();
}

Kolt side unwraps the pointer into a Handle automatically and passes it back on later calls. Free the struct in a matching close function.

kolt
import std "ffi"

try ffi.load("./libcounter.so")

// Automatically inferred as `ffi.Handle`
const h = try ffi.call("counter_new", ffi.KoltFFIPointer)

io.println(try ffi.call("counter_bump", ffi.KoltFFIInt, h)) // 1

Blocking Work ​

cpp
struct Job
{
    int64_t input;
    int64_t output;
};

// runs off the VM thread, touch no Kolt values here
void job_work(void *data)
{
    auto *job = static_cast<Job *>(data);
    job->output = job->input * job->input;
}

// runs back on the VM thread, build the result here
KoltValue job_done(KoltCtx raw_ctx, void *data)
{
    kolt::Context ctx(raw_ctx);
    auto *job = static_cast<Job *>(data);
    auto out = job->output;
    delete job;
    return ctx.make_int(out).release();
}

KoltValue heavy(KoltCtx raw_ctx, const KoltValue *args, int)
{
    kolt::Context ctx(raw_ctx);
    auto *job = new Job{ctx.get_int(args[0]), 0};
    return ctx.park_work(job_work, job_done, job).release();
}

Split the work in two. The work function blocks a background thread, the done function converts the result. Never call make_* or touch values inside the work function.

Cancellation ​

cpp
// bail out of long loops when the task was cancelled
for (int64_t i = 0; i < huge; i++)
{
    if (ctx.is_cancelled())
    {
        return ctx.make_error("cancelled").release();
    }
}

is_cancelled reports the calling task's cancel flag. is_preempting reports a time slice yield on tight loops.

Rust Extensions ​

rust
// same table, mirrored as a repr(C) struct (see examples/kolt.rs)
kolt_function!(my_add, |ctx, args| {
    // read args through the helper, build the result, release it
    let a = ctx.get_int(args[0]);
    let b = ctx.get_int(args[1]);
    ctx.make_int(a + b).release()
});

That sketch is only the shape. The working pattern lives in examples/math.rs: a KoltApi helper around the raw table, a LocalValue that frees on drop and releases on return, plus kolt_function! and kolt_init! macros that stamp out the exact entry point.

rust
kolt_init!(|ctx| {
    ctx.register("__rust_math.open", Some(open_db));
    ctx.register("__rust_math.close", Some(close_db));
});

kolt_extension_init with no_mangle and C ABI, same contract as the C++ side. Build it as a cdylib crate.

Building ​

bash
# linux, C++

bash
# macOS, C++
g++ -dynamiclib -o libmyext.dylib myext.cpp
bash
# windows, MSVC, C++
cl /LD myext.cpp
toml
# rust, in Cargo.toml of the extension crate
[lib]
crate-type = ["cdylib"]
bash
# rust build, the .so lands in target/release
cargo build --release

Loading And Calling ​

kolt
import std "ffi"

// fails when the file or kolt_extension_init is missing
try ffi.load("./libmyext.so")

// return tag types the call: KoltFFIInt, KoltFFIFloat,
// KoltFFIString, KoltFFIBuffer, KoltFFIBool, KoltFFIPointer,
// KoltFFIAny, KoltFFIVoid, KoltFFIArray, KoltFFITuple,
// KoltFFIMap, KoltFFINumber, KoltFFIBigInt, KoltFFIFunction
const sum = try ffi.call("my_add", ffi.KoltFFIInt, 3, 4)

Handle args unbox to raw pointers on the way in, pointer results wrap back into Handle. Anything else converts by value.

Raw C symbols without a Kolt entry point ​

kolt
import std "ffi"

// any shared library works, no kolt_extension_init needed
const libc = try ffi.open("libc.so.6")
const abs = libc.func("abs", ffi.I32, [ffi.I32])
io.println(try abs(-100)) // 100
libc.close()

lib.call(name, returnTag, paramTags, ...args) invokes one symbol with FFITag descriptors (ffi.I32, ffi.I64, ffi.U32, ffi.Pointer, ffi.CString), lib.func(...) returns a reusable typed closure, lib.close() unloads. Use this for plain C libraries, ffi.load plus ffi.call for Kolt extensions.
